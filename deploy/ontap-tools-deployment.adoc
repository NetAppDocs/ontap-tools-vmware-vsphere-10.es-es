= Implementa ONTAP tools como un appliance de un solo nodo
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Implementa las herramientas ONTAP para VMware vSphere como un dispositivo extrapequeño de un solo nodo compatible con almacenes de datos NFS y VMFS. El proceso de implementación tarda hasta 45 minutos.

.Antes de empezar
Si implementas una configuración de un solo nodo «extra pequeña», la biblioteca de contenidos es opcional. Para implementaciones de varios nodos o de alta disponibilidad (HA), la biblioteca de contenidos es obligatoria.

En VMware, una biblioteca de contenidos almacena plantillas de máquinas virtuales, plantillas de vApp y otros archivos. Usar una biblioteca de contenidos simplifica la implementación porque no depende del acceso directo a la red durante las operaciones con las plantillas.

Antes de crear una biblioteca de contenidos:

* Cree la biblioteca de contenido en un almacén de datos compartido para que todos los hosts del clúster puedan acceder a ella.
* Crea la biblioteca de contenidos antes de implementar las ONTAP tools for VMware vSphere OVA.
* Guarda la plantilla OVA en la biblioteca de contenidos tras la implementación.



NOTE: Si planeas habilitar la alta disponibilidad (HA) más adelante, implementa la máquina virtual de ONTAP tools en un clúster de ESXi o en un pool de recursos, no directamente en un host de ESXi.

Para crear una biblioteca de contenidos:

. Descarga las herramientas de ONTAP para VMware vSphere (archivos binarios _.ova_) y los certificados firmados desde https://mysupport.netapp.com/site/products/all/details/otv10/downloads-tab["Sitio de soporte de NetApp"^].
. Inicia sesión en el vSphere Client.
. En el menú de vSphere Client, selecciona *bibliotecas de contenidos*.
. Selecciona *Crear*.
. Introduce un nombre y crea la biblioteca de contenidos.
. Abre la biblioteca de contenidos que has creado.
. Selecciona *Acciones* > *Importar elemento* y importa el archivo OVA.



NOTE: Para más información, consulta https://blogs.vmware.com/vsphere/2020/01/creating-and-using-content-library.html["Creación y Uso de la Biblioteca de Contenido"].


NOTE: Antes de la implementación, configura el Distributed Resource Scheduler (DRS) del clúster en Conservador para evitar la migración de máquinas virtuales durante la instalación.

ONTAP tools for VMware vSphere se implementa inicialmente como una configuración sin HA. A partir de ONTAP tools 10.6, la incorporación en caliente de CPU y la incorporación en caliente de memoria están habilitadas por defecto. Para escalar a HA más adelante, estas funciones deben estar habilitadas.

.Pasos
. Descarga el archivo OVA de las ONTAP tools y los certificados firmados desde https://mysupport.netapp.com/site/products/all/details/otv10/downloads-tab["Sitio de soporte de NetApp"^]. Si ya has importado el OVA a tu biblioteca de contenidos, omite este paso.
. Inicie sesión en vSphere Server.
. Accede al pool de recursos, al clúster o al host donde quieras implementar el OVA.
+

IMPORTANT: No almacenes la máquina virtual de ONTAP tools en los almacenes de datos vVols que gestiona.

. Instala el archivo OVA desde la biblioteca de contenidos o desde el sistema local.
+
|===


| Del sistema local | De la biblioteca de contenido 


| a. Haga clic con el botón derecho del ratón y seleccione *Implementar plantilla OVF...*. b. Elija el archivo OVA de la URL o vaya a su ubicación y, a continuación, seleccione *Siguiente*. | a. Vaya a la biblioteca de contenidos y seleccione el elemento de biblioteca que desea implementar. b. Seleccione *Acciones* > *Nueva VM desde esta plantilla* 
|===
. En *Seleccionar un nombre y una carpeta*, introduce el nombre y la ubicación de la máquina virtual.
. Seleccione un recurso informático y seleccione *Siguiente*. Opcionalmente, marque la casilla para *encender automáticamente la VM implementada*.
. Revisa los detalles de la plantilla y selecciona *Siguiente*.
. Lea y acepte el contrato de licencia y seleccione *Siguiente*.
. Seleccione el almacenamiento para la configuración y el formato de disco y seleccione *Siguiente*.
. Seleccione la red de destino para cada red de origen y seleccione *Siguiente*.
. En la ventana *Personalizar plantilla*, introduce los valores necesarios. image:../media/custom-temp-p2.png["Personalizar plantilla"]
+
[IMPORTANT]
====
Los valores de la página *Personalizar plantilla* son obligatorios para que la implementación sea exitosa.

Presta especial atención a estos campos:

** *Nombre de host*: Introduce el nombre de host de la máquina virtual de ONTAP tools. Utiliza un formato de nombre de host válido.
** *Dirección IP de ONTAP tools*: Esta es la interfaz de gestión principal que se usa para acceder a ONTAP tools.
** *Dirección IPv4*: Esta es la dirección IP del nodo que se usa para el shell de diagnóstico y el acceso SSH para la resolución de problemas y el mantenimiento.


Si utilizas nombres DNS para el host o vCenter, asegúrate de que esos nombres se resuelvan correctamente en DNS.

====
+

NOTE: El nombre de host de vCenter es el nombre de la instancia de vCenter Server donde se implementa el dispositivo de herramientas ONTAP .

+
Si vas a implementar ONTAP tools en una topología de dos vCenter Server, donde el appliance está alojado en una instancia de vCenter y gestiona otra, asigna un rol restringido para la instancia de vCenter que aloja ONTAP tools. Crea un usuario y un rol dedicados de vCenter con solo los permisos necesarios para la implementación de plantillas OVF. Para más detalles, consulta link:../concepts/rbac-vcenter-use.html#vsphere-object-hierarchy["Roles incluidos con las herramientas de ONTAP para VMware vSphere 10"].

+
Para la instancia de vCenter gestionada por ONTAP tools, asegúrate de que la cuenta de usuario de vCenter tenga privilegios de administrador.

+
** Los nombres de host deben incluir letras (A-Z, a-z), dígitos (0-9) y guiones (-). Para la pila dual, especifica el nombre de host asociado a la dirección IPv6.
+

NOTE: No se admite IPv6 puro. Se admite el modo mixto con una VLAN que contenga tanto direcciones IPv6 como IPv4.

** La dirección IP de ONTAP tools (anteriormente load balancer) es el endpoint externo para ONTAP tools Manager (`\https://<ip>:8443/virtualization/ui/`), las llamadas a la API de REST y el acceso al complemento desde la interfaz de usuario de vCenter.
** La dirección IP virtual de ONTAP tools (anteriormente node interconnect) se asigna al servidor de la API de Kubernetes (kube-api) y actúa como la dirección IP virtual para el plano de control de Kubernetes.
** La dirección IPv4 es la dirección de gestión del nodo asociada al nombre de host especificado y se utiliza para el shell de diagnóstico y el acceso SSH.


. Revise los detalles en la ventana *Listo para completar*, seleccione *Finalizar*.
+
Cuando se inicia la tarea de implementación, el progreso se muestra en la barra de tareas de vSphere.

. Si no has seleccionado el encendido automático, enciende la máquina virtual una vez finalizada la tarea.


Realiza un seguimiento del progreso de la instalación desde la consola web de la máquina virtual.

Si hay discrepancias en el formulario OVF, aparece un cuadro de diálogo que te pide tomar medidas correctivas. Usa la tecla Tab para navegar, haz los cambios necesarios y selecciona *OK*. Tienes tres intentos para resolver los problemas. Si los problemas continúan después de tres intentos, la instalación se detiene y deberías volver a intentar la instalación en una nueva máquina virtual.
