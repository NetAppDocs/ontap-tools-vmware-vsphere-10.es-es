= Migra el proveedor VASA y actualiza el SRA en ONTAP tools
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Utiliza esta tarea para migrar el proveedor VASA desde ONTAP tools for VMware vSphere 9.xx a 10.6 y actualizar el Storage Replication Adapter (SRA) en el appliance VMware Live Site Recovery.



[[migrate-the-vasa-provider]]
== Migrar el proveedor VASA

.Antes de empezar
Asegúrate de que ONTAP tools for VMware vSphere 10.6 esté implementado y que el servidor vCenter de destino y los backends de almacenamiento estén listos para la migración.

. Para habilitar el puerto 1527 de Derby en el dispositivo ONTAP tools for VMware vSphere, habilita el usuario raíz, inicia sesión en la CLI a través de SSH y ejecuta el siguiente comando:
+
[listing]
----
iptables -I INPUT 1 -p tcp --dport 1527 -j ACCEPT
----
. Implementa el OVA de ONTAP tools for VMware vSphere 10.6.
. Añade la instancia de vCenter Server que quieres migrar a ONTAP tools for VMware vSphere 10.6. Consulta link:../configure/add-vcenter.html["Agregue una instancia de vCenter Server"] para más información.
. Integra el backend de almacenamiento localmente a través de las API de vCenter Server para el complemento ONTAP tools. Consulta link:../configure/add-storage-backend.html["Agrega un backend de almacenamiento usando la interfaz del cliente de vSphere"] para más información.
. Obtenga un token de acceso para autenticar solicitudes de API REST.  Utilice el siguiente ejemplo, reemplazando las variables con valores específicos de su entorno.
+
[source, curl]
----
curl --request POST \
  --location "https://$FQDN_IP_PORT/virtualization/api/v1/auth/vcenter-login" \
  --header "Content-Type: application/json" \
  --header "Accept: */*" \
  -d '{"username": "$MYUSER", "password": "$MYPASSWORD", "vcenter hostname": "$MYVCENTER"}'
----
+
Copie y guarde el token de acceso devuelto en la respuesta.

. Realiza la siguiente llamada a la API de migración desde Swagger o Postman.
+
[listing]
----
curl -X POST `\https://xx.xx.xx.xx:8443/virtualization/api/v1/vcenters/{vcguid}/migration-jobs`
----
+
Puedes acceder a Swagger a través de esta URL: `\https://$FQDN_IP_PORT/` , Por ejemplo: `\https://10.67.25.33:8443/` .

[[check-migration-status]]
=== Comprobar el estado de la migración

. Use el siguiente URI en Swagger para comprobar el estado:
+
[listing]
----
curl `\https://xx.xx.xx.xxx:8443/virtualization/api/jobmanager/v2/jobs/<JobId>?includeSubJobsAndTasks=true`
----
+
Usa el valor 'id' devuelto por el trabajo de migración en el paso anterior. Después de que el trabajo termine, revisa el informe de migración en la respuesta del trabajo.





[[register-and-verify-the-migrated-vasa-provider]]
=== Registrar y verificar el proveedor VASA migrado

. Registre el proveedor VASA con ONTAP tools for VMware vSphere. Para obtener instrucciones, consultelink:../configure/registration-process.html["Registre el proveedor de VASA de"] .
. Verifica el registro del proveedor VASA:
+
.. En el vSphere Client, ve al vCenter Server.
.. Selecciona *Configurar* > *Proveedores de almacenamiento*.
.. Confirma que el VASA Provider registrado en el paso anterior aparece en línea.


. Detenga el servicio del proveedor VASA de las ONTAP tools for VMware vSphere 9.10/9.11/9.12/9.13 mediante estos pasos:
+
.. En las herramientas ONTAP 9.x, abra la consola web.
.. Inicia sesión usando las credenciales de `maint`.
.. Ingresar `1` para seleccionar el menú *Configuración de la aplicación*.
.. Ingresar `5` para detener los servicios del Proveedor VASA y SRA.
.. En el vSphere Client, ve al vCenter Server y selecciona *Configurar* > *Proveedores de almacenamiento*.
.. Selecciona el VASA Provider offline para ONTAP tools 9.x y selecciona *Remove*.
+
Una vez detenido el antiguo VASA Provider, el servidor vCenter realiza una conmutación por error a ONTAP tools for VMware vSphere. Todos los datastores y máquinas virtuales se vuelven accesibles y son servidos desde ONTAP tools for VMware vSphere.



. Los almacenes de datos NFS y VMFS migrados aparecen en ONTAP tools for VMware vSphere 10.6 después de la tarea de detección de almacenes de datos, que puede tardar hasta 30 minutos. Comprueba su visibilidad en la página de resumen.

[[after-migration]]
== Tras la migración

Después de completar la migración y registrar ONTAP tools 10.6 con vCenter Server, sigue estos pasos:

* Espere a que se complete el *Descubrimiento* y el sistema actualice los certificados automáticamente en todos los hosts.
* Espere antes de iniciar las operaciones del almacén de datos y de la máquina virtual.  El tiempo de espera depende de la cantidad de hosts, almacenes de datos y máquinas virtuales.  Si no esperas, es posible que veas fallos ocasionales.


Después de la actualización, si el estado de cumplimiento de la máquina virtual es obsoleto, vuelva a aplicar la política de almacenamiento siguiendo los pasos siguientes:

. Vaya al almacén de datos y seleccione *Resumen* > *Políticas de almacenamiento de VM*.
. El sistema muestra el estado de cumplimiento en *Cumplimiento de la política de almacenamiento de VM* como *Desactualizado*.
. Seleccione la política de VM de almacenamiento y la VM correspondiente.
. Seleccione *Aplicar*.
. El estado de cumplimiento bajo *Cumplimiento de la política de almacenamiento de VM* se muestra como compatible.

[[update-the-storage-replication-adapter-sra]]
== Actualizar el adaptador de replicación de almacenamiento (SRA)

.Antes de empezar
Antes de migrar el SRA, comprueba lo siguiente:

* En el plan de recuperación, el sitio protegido es la ubicación donde las máquinas virtuales se están ejecutando actualmente y el sitio de recuperación es la ubicación donde se recuperarán las máquinas virtuales.
* En la interfaz del dispositivo VMware Live Site Recovery, un sitio aparece en estado protegido y el otro sitio aparece en estado de recuperación.
* En el plan de recuperación, los botones *CLEANUP* y *REPROTECT* están desactivados, y los botones *TEST* y *RUN* permanecen activados.



NOTE: No inicies la migración si la conmutación por error se ha completado pero la reprotección está pendiente. Asegúrate de que el proceso de reprotección se haya completado antes de proceder con la migración. Si hay una conmutación por error de prueba en curso, limpia la conmutación por error de prueba e inicia la migración.

. Siga estos pasos para eliminar el adaptador del SRA de herramientas de ONTAP para VMware vSphere 9.xx en VMware Site Recovery:
. Ve a la página de gestión de la configuración de VMware Live Site Recovery.
+
.. Vaya a la sección *Storage Replication Adapter*.
.. En el menú de puntos suspensivos, seleccione *Restablecer configuración*.
.. En el menú de puntos suspensivos, seleccione *Eliminar*.


. Lleve a cabo estos pasos en sitios de protección y recuperación.
+
.. link:../manage/enable-services.html["Habilite herramientas de ONTAP para los servicios de VMware vSphere"]
.. Configura ONTAP tools for VMware vSphere 10.6 SRA adapter usando los pasos en link:../protect/configure-on-srm-appliance.html["Configure el SRA en el dispositivo VMware Live Site Recovery"].
.. En la interfaz de VMware Live Site Recovery, ejecute *Discover Arrays* y *Discover Devices*.  Confirme que los dispositivos se muestren como antes de la migración.
