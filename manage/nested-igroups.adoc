= Gestión de igroups anidados en ONTAP tools
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Si trasladas almacenes de datos desde entornos no gestionados por ONTAP tools a entornos que sí lo están, debes comprender cómo se comportan los igroups. ONTAP tools for VMware vSphere utiliza un modelo de igroups anidados, lo que ayuda a explicar las diferencias de comportamiento entre versiones anteriores y la implementación actual.

A partir de ONTAP tools for VMware vSphere 10.4, ONTAP tools crea y mantiene automáticamente los objetos de ONTAP y de vCenter, lo que simplifica la gestión de los datastores en entornos de centros de datos de VMware. A partir de ONTAP tools for VMware vSphere 10.5 P2, ONTAP tools también elimina automáticamente los igroups migrados cuando ya no se usan.



[[quick-behavior-summary]]
== Resumen rápido del comportamiento

* Los almacenes de datos VMFS gestionados con ONTAP tools utilizan igroups anidados: un igroup padre por contexto de almacén de datos e igroups hijos por host.
* Las asignaciones LUN se aplican a los igroups hijos.
* Los igrupos padre personalizados pueden reutilizarse en todos los datastores.
* Los igroups migrados de ONTAP tools 9.x no se pueden reutilizar.




[[igroup-contexts]]
== Contextos de igroup

Las herramientas ONTAP para VMware vSphere manejan igroups en dos contextos.

.igroups administrados por herramientas que no son de ONTAP
Como administrador de almacenamiento, puedes crear igroups en el sistema ONTAP como estructuras planas o anidadas. La siguiente ilustración muestra un igroup plano creado directamente en ONTAP.

image:../media/non-otv-managed.png["igroup administrado por herramientas que no son de ONTAP"]

.igroups administrados por herramientas ONTAP
Cuando creas almacenes de datos, ONTAP tools for VMware vSphere crea igroups en una estructura anidada.

Por ejemplo, si creas datastore1 y lo montas en los hosts 1, 2 y 3, luego creas datastore2 y lo montas en los hosts 3, 4 y 5, ONTAP tools reutiliza el igroup a nivel de host para una gestión eficiente.

image:../media/otv-managed.png["igroup administrado por herramientas ONTAP"]

image:../media/otv-managed2.png["igroup administrado por herramientas ONTAP con igroup secundario reutilizado"]



[[naming-behavior]]
== Comportamiento de la nomenclatura

Cuando creas un almacén de datos y dejas el campo igroup en blanco, ONTAP tools crea una estructura igroup anidada por defecto.

* Patrón de nomenclatura de los igroup parentales: `otv_<vcguid>_<host_parent_datacenterMoref>_<datastore_name>`
* Patrón de nomenclatura de igroup infantil: `otv_<hostMoref>_<vcguid>`


La interfaz de sistemas de ONTAP muestra la relación entre los igroups padre e hijo en el campo *Parent Initiator Group*.

|===
| Escenario | Comportamiento del igroup parental | Comportamiento de igroup secundario | Asignación y visibilidad de LUN

El almacén de datos aparece en el inventario de vCenter Server. 


| Datastore creado con nombre de igroup personalizado | Se crea un igrupo padre personalizado con el nombre especificado. | Los igrupos hijos existentes a nivel de host se reutilizan cuando los hosts se solapan. | El nuevo LUN del almacén de datos se asigna al igrupo hijo reutilizado o recién creado. | Igroup personalizado existente reutilizado durante la creación del almacén de datos | Se selecciona y reutiliza un igroup padre personalizado existente. | Los igrupos hijos se reutilizan o amplían en función de la pertenencia al host. | El nuevo LUN del datastore se mapea a través del igrupo hijo asociado. El datastore aparece en vCenter Server.

[[custom-igroup-reuse-and-api-behavior]]
== Reutilización personalizada de igroups y comportamiento de la API

En la interfaz de usuario de las ONTAP tools, puedes reutilizar un igroup padre personalizado existente de la lista desplegable mientras creas un datastore.

El mismo comportamiento se admite a través de la API. Para reutilizar un igroup existente durante la creación del almacén de datos, proporciona el UUID del igroup en la carga útil de la solicitud de API.


NOTE: Sólo se pueden reutilizar los igroups personalizados. Los igroups migrados de ONTAP tools 9.x no se pueden reutilizar y, a partir de ONTAP tools 10.5 P2, se eliminan automáticamente cuando ya no se utilizan.



[[native-to-managed-conversion-view]]
== Vista de conversión de nativo a gestionado

Si creas el igroup y el almacén de datos directamente en los sistemas ONTAP y en los entornos VMware, ONTAP tools no gestiona estos objetos inicialmente, lo que da lugar a una estructura de igroup plana.

image:../media/vmfsds-native.png["Almacén de datos y igroup creados de forma nativa"]

Tras el descubrimiento del almacén de datos, ONTAP tools identifica y registra los igroups mapeados por el almacén de datos y luego los representa en un modelo anidado. El igroup padre se representa en el nivel del almacén de datos, el igroup existente se renombra con el prefijo  `otv_` como igroup hijo y las asignaciones del iniciador permanecen sin cambios.

image:../media/otv-ds.png["Almacén de datos e igroup administrados por herramientas ONTAP"]

ONTAP tools for VMware vSphere no detecta ni gestiona los igroups que se crean en los sistemas ONTAP pero que no están asignados a un datastore ni vinculados a ONTAP tools. Durante el descubrimiento, ONTAP tools solo convierte los igroups que están asignados a los datastores descubiertos; los demás igroups permanecen sin gestionar.



[[reuse-of-discovered-native-igroups]]
== Reutilización de los igroups nativos descubiertos

Después de que ONTAP tools gestione un igroup nativo descubierto, ese igroup estará disponible en la lista desplegable de nombres de grupos de iniciadores personalizados para la creación de datastores.

El nuevo LUN del datastore se asigna al igrupo hijo normalizado, por ejemplo, `otv_NativeIgroup1`.

ONTAP tools for VMware vSphere no detecta ni utiliza igroups creados en sistemas ONTAP que no están gestionados por ONTAP tools o que no están vinculados a un datastore.
